1. COMPRENDRE : VOTRE SYSTÈME ACTUEL VS LE VRAI ENTRAÎNEMENT (FINE-TUNING)
================================================================================

Dans votre application actuelle Tradition IA (api/_knowledge.js, api/chat.js),
vous utilisez une méthode appelée le "PROMPT SYSTÈME" (In-Context Learning) :
- À chaque message de l'utilisateur, votre serveur envoie une grosse liste de mots
  et de phrases en Fang, Punu, Myènè... au modèle généraliste (DeepSeek ou OpenAI).
- Le modèle "lit" ces notes dans sa mémoire immédiate et essaie de répondre.

AVANTAGES DU SYSTÈME ACTUEL :
- Très rapide à modifier (on ajoute une ligne dans _knowledge.js et c'est actif).
- Pas besoin de carte graphique ni de calculs lourds.

LIMITES DU SYSTÈME ACTUEL :
- Les modèles généraux comme DeepSeek, Llama ou GPT ne connaissent pas la grammaire
  profonde des langues bantoues du Gabon.
- Si le texte à traduire est complexe ou n'est pas mot à mot dans la liste, le
  modèle peut inventer (hallucination).
- Le prompt système consomme des tokens à chaque requête.

CE QU'EST LE VRAI ENTRAÎNEMENT (FINE-TUNING) :
- On prend un grand modèle de base (ex: LLaMA 3 8B, Mistral 7B ou Qwen 2.5 7B).
- On lui injecte des milliers d'exemples de traductions, dialogues et proverbes
  gabonais en modifiant directement les poids neuronaux du modèle (technique LoRA).
- Le modèle "apprend" pour de bon : il comprend la morphologie, les préfixes
  de classe nominale, la syntaxe et les expressions gabonaises SANS avoir besoin
  qu'on lui réinjecte un dictionnaire à chaque question.

================================================================================
3. LES OUTILS & BIBLIOTHÈQUES À INSTALLER
================================================================================

Pour entraîner votre IA, voici les 5 bibliothèques reines :

1. PyTorch (`torch`) :
   Le moteur mathématique de base créé par Meta qui gère les calculs sur GPU.

2. Hugging Face Transformers (`transformers`) :
   La plateforme mondiale de partage de modèles d'IA (Llama, Mistral, Gemma...).

3. Hugging Face TRL (`trl` - Transformer Reinforcement Learning) :
   Fournit la classe `SFTTrainer` (Supervised Fine-Tuning Trainer) conçue
   spécifiquement pour entraîner une IA à suivre des instructions.

4. PEFT & BitsAndBytes (`peft`, `bitsandbytes`) :
   Permettent le QLoRA (Quantized Low-Rank Adaptation). Cela réduit l'usage de
   mémoire GPU de 80% ! Un modèle de 8 milliards de paramètres qui demandait
   autrefois 32 Go de VRAM peut désormais s'entraîner sur un simple GPU de 16 Go
   ou sur Google Colab (carte T4 gratuite).

5. Unsloth (`unsloth`) :
   L'outil le plus rapide et le plus populaire actuellement. Il accélère
   l'entraînement de 2x à 5x tout en divisant la mémoire nécessaire par 2.

6. ÉTAPE 2 : LE SCRIPT PYTHON D'ENTRAÎNEMENT COMPLET (FINE-TUNING LoRA / QLoRA)
================================================================================

Voici le code du script `entrainer_modele.py` disponible à la racine du projet :

--------------------------------------------------------------------------------
import os
import sys
import torch
from datasets import load_dataset
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
    TrainingArguments
)
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from trl import SFTTrainer

# 1. Modèle de base recommandé
MODEL_ID = "Qwen/Qwen2.5-7B-Instruct"
OUTPUT_DIR = "./tradition_ia_modele_entraine"
DATASET_FILE = "dataset_tradition_ia.jsonl"

# 2. Quantification 4-bit (QLoRA)
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16 if torch.cuda.is_available() and torch.cuda.is_bf16_supported() else torch.float16,
    bnb_4bit_use_double_quant=True,
)

# 3. Chargement du tokenizer et du modèle
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, trust_remote_code=True)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=bnb_config if torch.cuda.is_available() else None,
    device_map="auto" if torch.cuda.is_available() else "cpu",
    trust_remote_code=True
)

if torch.cuda.is_available():
    model = prepare_model_for_kbit_training(model)

# 4. Configuration LoRA
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj", "gate_proj", "up_proj", "down_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()

# 5. Chargement et formatage du dataset
dataset = load_dataset("json", data_files=DATASET_FILE, split="train")

def formater_prompts(batch):
    textes = []
    for conversation in batch["messages"]:
        texte_formate = tokenizer.apply_chat_template(
            conversation,
            tokenize=False,
            add_generation_prompt=False
        )
        textes.append(texte_formate)
    return {"text": textes}

dataset = dataset.map(formater_prompts, batched=True)

# 6. Hyperparamètres d'entraînement
training_args = TrainingArguments(
    output_dir=OUTPUT_DIR,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,
    optim="paged_adamw_8bit" if torch.cuda.is_available() else "adamw_torch",
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    save_strategy="epoch",
    logging_steps=10,
    num_train_epochs=5,
    fp16=torch.cuda.is_available() and not torch.cuda.is_bf16_supported(),
    bf16=torch.cuda.is_available() and torch.cuda.is_bf16_supported(),
    report_to="none"
)

# 7. Lanceur SFTTrainer
trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    peft_config=lora_config,
    dataset_text_field="text",
    max_seq_length=1024,
    tokenizer=tokenizer,
    args=training_args
)

print("🚀 Démarrage de l'entraînement...")
trainer.train()

# 8. Sauvegarde
trainer.model.save_pretrained(OUTPUT_DIR)
tokenizer.save_pretrained(OUTPUT_DIR)
print("🎉 Entraînement terminé !")

7. LES FONCTIONS PHARES DU FINE-TUNING (DÉCORTIQUÉES EN DÉTAIL)
================================================================================

Voici l'explication précise de chaque fonction essentielle utilisée dans le code :

1. `AutoTokenizer.from_pretrained(MODEL_ID)` :
   - Rôle : Les ordinateurs et les IA ne lisent pas des lettres, mais des nombres.
     Le tokenizer découpe le texte gabonais en petits morceaux (mots ou syllabes
     appelés "tokens") et leur attribue un numéro unique d'identification.

2. `BitsAndBytesConfig(load_in_4bit=True, ...)` :
   - Rôle : C'est la fonction magique du QLoRA. Normalement, un modèle de 7 milliards
     de paramètres pèse 28 Go de VRAM. Cette fonction compresse les poids en 4 bits,
     ce qui fait chuter le besoin en mémoire à seulement 5,5 Go de VRAM sans perdre
     la qualité linguistique !

3. `AutoModelForCausalLM.from_pretrained(...)` :
   - Rôle : Télécharge et instancie le réseau de neurones complet du modèle de base
     (ex: Qwen 2.5 ou Mistral). L'argument `device_map="auto"` répartit
     automatiquement le modèle sur votre GPU ou RAM.

4. `prepare_model_for_kbit_training(model)` :
   - Rôle : Gèle les milliards de poids du modèle original en lecture seule et prépare
     les couches d'attention pour recevoir les gradients de calcul lors du LoRA.

5. `LoraConfig(r=16, lora_alpha=32, target_modules=...)` :
   - Rôle : Configure la taille et l'emplacement des adaptateurs LoRA.
     * `r=16` (Rang) : Nombre de dimensions de la matrice adaptatrice.
     * `lora_alpha=32` : Intensité avec laquelle les nouvelles connaissances sur les
       langues gabonaises vont influencer les réponses finales de l'IA.
     * `target_modules` : Les matrices d'attention du modèle où sont greffés les adaptateurs.

6. `get_peft_model(model, lora_config)` :
   - Rôle : Greffe les adaptateurs LoRA sur le modèle. Après cette fonction, seulement
     0,1% à 0,2% des paramètres sont modifiables, ce qui rend l'entraînement
     ultra-rapide et ultra-léger.

7. `tokenizer.apply_chat_template(conversation)` :
   - Rôle : Convertit le dictionnaire JSON (`messages`) au format brut attendu par
     l'architecture du modèle (par exemple en ajoutant les balises `<|im_start|>system...`,
     `<|im_start|>user...`, `<|im_start|>assistant...`).

8. `TrainingArguments(...)` :
   - Rôle : Pilote tout le comportement mathématique de l'apprentissage :
     * `learning_rate=2e-4` : La vitesse à laquelle les neurones corrigent leurs erreurs.
     * `per_device_train_batch_size` : Combien de phrases l'IA analyse en même temps.
     * `gradient_accumulation_steps` : Simule un gros lot de données pour stabiliser l'apprentissage.
     * `num_train_epochs=5` : Le nombre de fois que l'IA va relire l'intégralité du dataset.

9. `SFTTrainer(...)` (Supervised Fine-Tuning Trainer de Hugging Face TRL) :
   - Rôle : Le grand chef d'orchestre. Il prend le modèle, les adaptateurs, vos données
     gabonaises et gère la distribution des calculs, le masquage des invites et la perte (loss).

10. `trainer.train()` :
    - Rôle : LA fonction reine ! Elle lance la grande boucle d'entraînement (forward pass,
      calcul de l'erreur via la Cross-Entropy Loss, backward pass et descente de gradient).

11. `trainer.model.save_pretrained(OUTPUT_DIR)` :
    - Rôle : Enregistre sur votre disque dur les adaptateurs LoRA créés (généralement un petit
      dossier de moins de 100 Mo contenant `adapter_model.safetensors` et `adapter_config.json`).

12. `PeftModel.from_pretrained(base_model, LORA_PATH)` & `model.generate(...)` :
    - Rôle : Utilisées lors du test (`tester_modele.py`). Elles fusionnent à la volée le modèle
      de base avec vos adaptateurs et génèrent les réponses token par token.

LES 7 PANNES LES PLUS FRÉQUENTES ET COMMENT S'EN SORTIR TOUT SEUL :
--------------------------------------------------------------------------------

PANNE 1 : `OutOfMemoryError: CUDA out of memory` (La mémoire GPU est saturée)
  Cause : Le modèle ou la longueur des phrases est trop grand pour votre carte.
  Solution :
  - Dans `training_args`, réglez `per_device_train_batch_size = 1`.
  - Augmentez `gradient_accumulation_steps = 8` ou `16`.
  - Dans `SFTTrainer`, descendez `max_seq_length` de 1024 à 512.
  - Ajoutez `gradient_checkpointing=True` dans vos arguments d'entraînement.

PANNE 2 : `bitsandbytes` échoue sous Windows (`CUDA Setup failed / DLL not found`)
  Cause : Windows et bitsandbytes ont souvent des incompatibilités de drivers CUDA.
  Solution débrouille :
  - Tapez : `pip install bitsandbytes-windows`
  - OU bien, la solution la plus intelligente : ne perdez pas 3 heures à vous battre
    avec Windows, ouvrez Google Colab (Linux) en 1 clic et faites tourner l'entraînement
    sur leur machine virtuelle où tout est déjà préconfiguré !

PANNE 3 : `Torch not compiled with CUDA enabled`
  Cause : Vous avez installé la version CPU de PyTorch au lieu de la version GPU.
  Solution :
  - Désinstallez torch : `pip uninstall torch`
  - Réinstallez la version CUDA depuis le site officiel :
    `pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121`

PANNE 4 : La perte (`loss`) vaut `nan` ou ne descend jamais
  Cause : Votre taux d'apprentissage est trop violent ou des données sont corrompues.
  Solution :
  - Baissez `learning_rate` : passez de `2e-4` à `5e-5` ou `1e-4`.
  - Vérifiez dans votre fichier `dataset_tradition_ia.jsonl` qu'il n'y a pas
    de ligne vide ou de phrase vide `""`.

PANNE 5 : L'entraînement est ultra-lent (plusieurs heures pour 100 exemples)
  Cause : Le script tourne sur votre processeur (CPU) au lieu de votre carte graphique.
  Solution :
  - Vérifiez dans Python : `import torch; print(torch.cuda.is_available())`.
    Si cela affiche `False`, votre GPU n'est pas détecté.

PANNE 6 : Le modèle répète en boucle la même phrase ou oublie tout
  Cause : Phénomène d'"overfitting" (sur-apprentissage) ou de "catastrophic forgetting".
  Solution :
  - Réduisez le nombre d'époques : passez de 5 époques à 2 ou 3 époques.
  - Enrichissez votre jeu de données avec plus de variété de questions.

PANNE 7 : Vous n'avez pas de PC puissant et Google Colab se déconnecte ?
  Alternatives gratuites dans le cloud :
  - Kaggle (https://www.kaggle.com) : offre 30 heures par semaine de GPU double T4 gratuit !
  - Lightning AI (https://lightning.ai) : crédits mensuels gratuits pour lancer du PyTorch.
  - OpenAI Fine-Tuning : vous uploadez simplement `dataset_tradition_ia.jsonl` sur
    la plateforme OpenAI et ils entraînent un `gpt-4o-mini` personnalisé pour quelques centimes,
    sans que vous n'ayez besoin d'écrire une seule ligne de GPU.

11. ÉTAPE 4 : CONNECTER LE MODÈLE ENTRAÎNÉ À NOTRE APPLICATION TRADITION IA
================================================================================

Une fois que votre modèle est entraîné, comment le relier à votre site web
Tradition IA (api/chat.js et api/translate.js) ?

Trois chemins s'offrent à vous :

MÉTHODE 1 : AVEC OLLAMA (Local & Gratuit)
1. Exportez vos adaptateurs LoRA fusionnés en format `.gguf`.
2. Créez un fichier `Modelfile` :
   FROM ./tradition_ia.gguf
   SYSTEM "Tu es Mbolo IA, l'expert des traditions gabonaises créé par Rosny OTSINA."
3. Lancez : `ollama create mbolo-ia -f Modelfile` puis `ollama run mbolo-ia`.
4. Dans `api/chat.js`, pointez simplement vers : `http://localhost:11434/v1/chat/completions`.

MÉTHODE 2 : HÉBERGEMENT SERVEUR DÉDIÉ (Hugging Face Inference ou RunPod)
1. Uploadez votre modèle sur votre compte Hugging Face (`huggingface-cli upload`).
2. Déployez un endpoint API sécurisé.
3. Dans votre Vercel (`Settings -> Environment Variables`), remplacez votre clé
   OpenRouter par votre endpoint Hugging Face personnel.

MÉTHODE 3 : FINE-TUNING CLOUD OPENAI (Le plus simple en production)
Si vous ne voulez pas gérer de serveur GPU 24h/24 :
1. Utilisez votre fichier `dataset_tradition_ia.jsonl`.
2. Lancez le job de fine-tuning chez OpenAI (gpt-4o-mini).
3. Vous obtenez un nom de modèle (ex: `ft:gpt-4o-mini:tradition-ia-2026`).
4. Dans `api/chat.js`, modifiez la variable `DEFAULT_MODEL` pour pointer dessus.
